## 生命周期与使用规则

文档生命周期统一使用：

- **CURRENT**：当前权威入口或仍有效的维护记录；不代表相关功能已通过全部验收。
- **PENDING**：当前仍待决策、实施或验证的材料；执行前必须核对适用基线与授权。
- **HISTORICAL**：历史方案、评审、已完成缺陷/验收阶段材料；保留审计上下文，不作为当前执行指令。
- **RETIRED**：已被替代且不再作为工作依据；仅在有追溯价值时保留。

生命周期状态与测试结果（PASS/FAIL/EXPECTED/SKIP/NOT_COVERED）相互独立。文档标为 CURRENT 不代表其中每项测试仍然有效；历史报告中的 PASS 也不能代替当前版本复测。

## 文档与测试资产维护约定

- 根 README 负责项目入口、架构概览和可执行测试入口说明；本文件负责文档导航；专项文档负责详细方案、步骤、判定和证据。三者不互相替代。
- 新增、移动、重命名、归档或删除文档时，同步更新本索引、根 README 中受影响的链接，以及仓内所有入链引用。
- 当前维护入口只列当前权威材料；历史材料必须标注生命周期和适用边界，不能让旧 T3/T4/T5/T6 计划或报告看起来像当前测试指令。
- 测试计划、执行报告、原始证据和历史缺陷分层管理。测试结果状态独立记录，必须包含客户端提交、设备身份、固件版本/build SHA、平台环境和证据来源。
- 一次性脚本优先放在仓库外；可复用工具进入 `tools/`，并说明用途、依赖、参数、示例、副作用和产物/清理方式。页面、用例和脚本应说明前置条件、设备副作用、判定标准及清理/恢复方法。
- 每轮专项结束盘点重复、过期的测试说明与脚本。清理前全仓搜索页面路由、菜单、require/import、构建脚本、README、自动化调用和文档引用，形成保留/归档/候删清单；未获授权不删除。
- 不得删除已签收验收记录、原始日志/抓包/截图、事故证据、缺陷复现最小用例或仍有回归价值的测试；归档应保留原始日期、版本和哈希。
- 索引链接必须有效。文档中的测试状态不自动代表当前状态；每次执行前核对对应代码、固件 Contract、设备镜像和最新证据。
